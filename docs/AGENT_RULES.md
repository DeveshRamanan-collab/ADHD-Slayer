## OM-7 — Usage-limit interruptions cost nothing
Claude Max meters a rolling 5-hour window, a rolling 7-day window and per-model-family limits at the same time. At a limit Claude Code shows "You've hit your session limit · resets <time>" (or weekly/Opus/Sonnet), pauses, and — where the installed version supports automatic continue and it is on (Devesh is asked to enable it; Phase 0.1 records it as a verified `FACT-`) — resumes by itself after the reset with a fixed continuation prompt; otherwise the session ends and Devesh restarts with `03_RESUME_PROMPT.md`. A weekly reset more than 24 hours away does not auto-resume; Devesh restarts with `03_RESUME_PROMPT.md`. None of this is an error.
1. **Disk is the only memory.** Assume the session can be cut at any tool call and resumed hours or days later in a fresh context. Everything needed to continue lives in the OM-5 files, the cache and Git.
2. **Writes are atomic units.** A deliverable is never left half-written without the `.PARTIAL.md` convention.
3. **Subagents persist their own results** to disk with the end marker before returning. A subagent running when the limit hit is treated as not run; on resume, re-dispatch only the briefs whose owned files are incomplete.
4. **Figma reads are ledgered and cached by hooks** before analysis; nothing about a read lives only in context.
5. **Git is the checkpoint:** commit after every completed document, gate and read batch.
6. **On continuation** (first turn after "Usage limit reset · continuing automatically", or a fresh session whose first message is the resume prompt): run the OM-5 resume protocol before any other action.
7. **Never manage billing or models to dodge a limit.** No `/usage-credits`, `/model`, `/login`, `/config`; no model switch; no edits to `~/.claude/settings.json`. If the footer shows a wait, do nothing. Devesh decides billing.
8. **Report usage at gates:** one line in each gate file, "Usage at gate: <what /usage shows, or 'not checked'>". Usage is never a reason to sample, shorten or skip.
9. **Order bursts** (per-page analyses, per-framework research, per-topic legal research) so the most reasoning-heavy pieces run first and every piece is independent: a mid-burst cut loses one subagent, not the batch.
10. A `StopFailure` hook appends `API_ERROR at <ISO>: <message>` to the PROGRESS log so the resume protocol and Devesh can see why a turn ended.
